# 编译、烧录和首次上板

## 1. 先选对HEX

第一轮只测按键/LED，用[bringup固件](releases/v0.1.1/bringup/simplekvm_bringup.hex)：它始终保持USB数据断开，不会自动亮任何指示灯，全部释放稳定后逐键按下才点亮对应灯。

测完整USB功能，用[dev固件](releases/v0.1.1/dev/simplekvm_dev.hex)：约百毫秒启动等待后默认电脑4、LED4亮；其它按键可切换电脑。

准备长期运行验证，再用[release固件](releases/v0.1.1/release/simplekvm_release.hex)：行为相同，但启用独立看门狗。它尚未完成实板超时、波形与USB兼容性验收。

## 2. WCH-LinkE接线

本板经正常USB输入或受控电源路径供电，先共地，再连接下载信号。

| H1脚位 | 本板信号 | WCH-LinkE |
| --- | --- | --- |
| 1 | SWIO，PD1/U8.18 | SWDIO/TMS |
| 2 | NRST，PD7/U8.4 | RST，建议接，便于恢复 |
| 3 | GND | GND |

下载器切为RISC-V/SDI模式；本板已供电时不接其5V/3V3输出，SWCLK/TCK不接。当前固件保留PD1调试和PD7复位，不使用串口或USB升级，不写调试关闭/读保护等选择字。

在WCH-LinkUtility或支持CH32V003的MounRiver下载功能中选择器件，载入对应HEX，执行编程、校验、复位运行。HEX包含地址信息，优先用HEX，不手工套用其它芯片的BIN地址。

本工程沿用官方CH32V003链接脚本：**ELF入口及Flash链接原点为0x00000000**。BIN只是同一镜像的原始字节，烧录器的物理映射/别名参数需按CH32V003工具核对。本轮没有实测BIN烧录地址别名；旧硬件文档中泛用的0x08000000描述不作为本固件的直接烧录指令。

## 3. 首次验证顺序

1. 下载bringup并校验。确认EN#持续高；全部松键20ms后，SW1～SW4依次对应LED1～LED4。此镜像不接通数据，电脑无法识别外设属于预期。
2. 下载dev。上电LED先全灭，之后只亮LED4。按SW1～SW3检查对应灯，再用逻辑分析仪看PD2、PC6、PC7：先断开，改变选择位后等待，再接通。
3. 接入电脑与低功耗键鼠，验证所有目标切换。LED只代表通道，不代表枚举完成。
4. 验证三个A口和一个C口；Type-C用支持数据的线，正反插均测。VBUS常供电和无主机在线检测的硬件边界仍存在。
5. 最后下载release，测停止主循环/节拍后的看门狗复位，再进行长期循环。记录每台电脑和外设型号，不只检查灯。

本版未写Flash记忆，掉电、NRST或看门狗复位后都默认电脑4。正常切换只断数据，不主动关闭键鼠电源。

## 4. 从源码重新构建

需要Windows和Python 3.9及以上。打开终端进入本文件所在目录，执行：

```powershell
python tools/bootstrap_tools.py
python tests/test_behavior.py
python tools/build.py --profile all
```

bootstrap只下载便携工具到临时目录，校验固定SHA-256后解压，不安装系统组件。跨平台的逻辑代码独立于芯片库；当前提供的下载/测试脚本按Windows编译器组合验证。

工具来源：MounRiver 1.92的Windows GCC8分包，来自[社区镜像的固定资产](https://github.com/ch32-riscv-ug/MounRiver_Studio_Community_miror/releases/download/1.92-toolchain/riscv-none-embed-gcc-8-win-1.92.zip)，不是本次从原厂站直接下载。原厂旧链接本轮返回HTML，因此明确保留镜像来源和已取得文件哈希。TinyCC来自[上游GNU Savannah发布](https://download.savannah.gnu.org/releases/tinycc/tcc-0.9.27-win64-bin.zip)，只用于电脑端行为测试。

| 工具 | 版本 | 下载文件SHA-256 |
| --- | --- | --- |
| 固件编译器 | MounRiver GCC8，xPack 8.2.0，32位Windows | da97b5f50fd20394d844fc02c2bb034f668019b9db62b86a3f15fa277f2831fd |
| 电脑端测试编译器 | TinyCC 0.9.27，Windows x64 | 34a721949a2583fdff725312da092fa0f5f1f284b702e6f811c6954714faabb2 |

已有对应MounRiver工具链时可直接指定：

```powershell
python tools/build.py --profile dev --gcc "C:/MounRiver/toolchain/RISC-V Embedded GCC/bin/riscv-none-embed-gcc.exe"
python tests/test_behavior.py --cc "C:/tools/tcc/tcc.exe"
```

旧GNU/TinyCC工具安装路径使用英文，工程可放在中文目录，脚本从工程内用相对路径调用。固件输出在build/bringup、build/dev、build/release，分别包含HEX、BIN、ELF、map、反汇编、源文件哈希和构建日志。

App源文件使用-Wall、-Wextra、-Werror编译。目标为rv32ec/ilp32e，内部HSI 24MHz，TIM2节拍1ms，链接时保留512字节栈并检查RAM不重叠。构建还检查TIM2向量确实指向实际处理函数。

SDK选取自[WCH原厂仓库固定提交](https://github.com/openwch/ch32v003/tree/4e1b7437ada5d3ae8831a6f4b811a6320e4e23c7)。Vendor文件不改动，时钟与链接脚本的派生副本放在Project，修改记录见Vendor/WCH/README.md。

## 5. 调试变量与未完成项

ELF保留g_debug：版本、时钟值、毫秒计数、状态、active/pending、按键掩码、解锁状态、连接计数、复位标志、最后故障和mcause。无需串口日志，不占用按键引脚。

DEV下暂停调试不会被本程序看门狗复位。恢复后若按键采样间隔过长，需全部松开后重新按。RELEASE运行配置不保证长时间断点仍保持原状态，应先用DEV定位问题。

电脑端测试和交叉编译已做；实板下载、振荡器时序误差、实际看门狗超时、电源完整性和四电脑USB枚举尚未执行。没有依据将这些项目标成已通过。
