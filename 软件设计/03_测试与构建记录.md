# v0.1.1测试与构建记录

原始构建日期：2026-10-26；开源资料更新：2026-10-29。对象：v0.1.1默认通道调整版固件与当前发布资料。

## 1. 已完成

- 已实现四键、四灯、先断后接、默认电脑4、无掉电记忆、多键锁定、切换覆盖和异常断开。
- 23项电脑端行为测试通过。测试载入实际key.c、switch_ctrl.c、health.c代码，由TinyCC编为Windows x64 DLL，通过Python提供可控时间和硬件事件记录。
- 测试包括全部12种有向通道切换、20ms边界与抖动、10秒长按、启动按住、多键先后重叠、采样停顿、GAP/SETTLE覆盖、旧接通截止时刻的新按键优先、32位计时回绕、非法状态/目标、硬件拒绝以及喂狗资格。
- 额外执行10000步固定种子的随机请求/按键组合，检查选择位只在断开时改变、LED与通道一致、不会进入错误接通。
- 三种目标固件交叉编译通过，App源文件使用-Wall/-Wextra/-Werror；ELF均为RISC-V RV32EC/ILP32E，实际TIM2中断向量绑定检查通过。
- 固件GPIO掩码、四键、LED阴极与限流、选择/使能及H1对照历史`2026-10-21-2` ENET检查通过。当前10月29日硬件工程没有同版本ENET，不能沿用该结果宣称新版网表已自动验证。
- 28个Vendor文件与固定原厂提交的SHA-256一致。独立Project派生的时钟/链接改动有记录。

测试不只是检查常量或配置表：它检查真实C代码的事件数量、断开/选择/接通顺序、禁止旧pending短暂接通，以及无新节拍/故障时拒绝喂狗。电脑端未运行目标MMIO驱动，不能取代上板。

## 2. 构建占用

| 配置 | Flash镜像 | 静态RAM | 预留栈 | 看门狗 |
| --- | --- | --- | --- | --- |
| bringup | 2460字节 | 132字节 | 512字节 | 关闭 |
| dev | 2840字节 | 132字节 | 512字节 | 关闭 |
| release | 3040字节 | 132字节 | 512字节 | 开启 |

芯片容量为16KB Flash、2KB SRAM。静态RAM与预留栈分开统计；编译器逐函数栈用量在.su文件中，512字节为链接预留，不是已测得的最坏中断嵌套用量。ELF调试信息不计入实际Flash镜像大小。

固件编译器为MounRiver 1.92分发的xPack GCC8.2.0。SDK固定提交为4e1b7437ada5d3ae8831a6f4b811a6320e4e23c7。Flash链接原点为0x00000000；公开HEX/BIN的哈希见`releases/v0.1.1/SHA256SUMS.txt`。为避免泄露本机路径，发布包不含原构建日志；按本文复现命令重新构建时会在本地生成配置JSON、源文件快照与日志。

## 4. 复现入口

```powershell
python tools/verify_hardware.py
python tests/test_behavior.py
python tools/build.py --profile all
python tools/package.py
```

默认硬件校验只检查当前EDA工程、PDF、BOM的固定哈希与固件GPIO掩码；因为当前未附同版本ENET，它不执行新版逐网连接检查。首次运行先按02文档准备便携编译器。打包脚本检查构建源文件、测试源文件和生成物哈希是否仍一致，拒绝把修改后的源码与旧HEX混装。
